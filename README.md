# Кварта — лендинг обжарки кофе (тестовое задание)
 
Одностраничный лендинг с формой заявки. Заявка сохраняется в SQLite и дублируется менеджеру в Telegram вместе с данными о рекламном источнике.
 
- Сайт: https://coffee-tz.work.gd/
- IP-адрес сервера: 65.21.189.102
 
## Стек
 
| Часть | Технологии |
|---|---|
| Фронтенд | React 18 + Vite, обычный CSS |
| Бэкенд | FastAPI, Pydantic, aiosqlite, aiogram |
| БД | SQLite (файл в Docker volume) |
| Инфраструктура | Docker Compose, nginx, GitHub Actions, VPS на Hetzner |
 
## Как это работает
 
```
браузер ──► nginx (контейнер web) ──► статика React
                    └── /api/* ──► FastAPI (контейнер backend) ──► SQLite (volume)
                                                └──► Telegram-бот ──► чат менеджера
```
 
nginx отдаёт собранный фронт и проксирует `/api/*` на бэкенд. Бэкенд наружу напрямую не открыт.
 
### Форма и требования ТЗ
 
- **Поля:** имя, телефон, что интересует (подписка / разовый заказ / вопрос), комментарий.
- **Телефон.** Принимаются белорусские мобильные номера (`+375` / `375` / `80`, коды 25, 29, 33, 44) в любом написании, на бэкенде приводятся к виду `+375XXXXXXXXX`. Неверный номер не принимается, под полем показывается подсказка с примером формата. Проверка есть и на фронте, и на бэкенде. Городские номера не принимаются, это моё допущение.
- **Источник заявки.** При загрузке страницы из адреса читаются `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid`, `fbclid`, `yclid`, плюс адрес страницы (`landing_url`) и `referrer`. Данные хранятся в `sessionStorage`, уходят вместе с заявкой, лежат в отдельных колонках таблицы `leads` и показываются менеджеру в Telegram. Для рекламы нужны ссылки с метками, например:
  `https://coffee-tz.work.gd/?utm_source=instagram&utm_medium=cpc&utm_campaign=autumn&utm_content=banner_2`
- **Ошибка отправки.** Если запрос не прошёл (нет сети, таймаут 15 с, ошибка сервера), над формой появляется сообщение с причиной, кнопка «Отправить ещё раз» и телефон для связи. Введённые данные остаются в форме.
- **Дубли.** Повторная заявка с тем же номером в течение 10 минут не создаёт новую запись. Бэкенд возвращает `200` и id уже существующей заявки, клиент видит обычное «Заявка отправлена». Проверка и вставка идут под `asyncio.Lock`, поэтому двойной клик и параллельные запросы дубль не создают. На фронте кнопка блокируется на время запроса.
- **Telegram.** После сохранения заявки в БД в чат уходит сообщение (имя, телефон, интерес, комментарий, источник). Отправка идёт в фоне, до трёх попыток с задержкой. Если Telegram недоступен, заявка уже сохранена и клиент ничего не замечает. Для дублей сообщение не отправляется.
### API
 
| Метод | Путь | Ответы |
|---|---|---|
| POST | `/api/leads` | `201` создана, `200` дубль, `422` ошибки валидации `{message, fields:[{field, message}]}`, `503` ошибка записи в БД |
| GET | `/api/health` | `200 {"status":"ok"}` |

## Запуск
 
Локально через Docker:
 
```bash
docker compose up --build        # сайт на http://localhost
```

Без Docker: `cd backend && uvicorn app.main:app --reload` и `cd frontend && npm install && npm run dev` (запросы `/api` проксируются на бэкенд).
 
Тесты: `cd backend && python -m pytest`. Они покрывают валидацию формы, дедупликацию и отправку в Telegram.
 
## Деплой
 
GitHub Actions при пуше в `main`:
 
1. запускает тесты бэкенда;
2. собирает образы бэкенда и фронтенда и публикует их в GHCR;
3. по SSH копирует `docker-compose.yml` на сервер, делает `docker compose pull && up -d` и проверяет `/api/health`. Если сервис не ответил, джоб падает и выводит логи.
База хранится в volume `leads-data` и переживает обновления.
 
## Почему SQLite, а не файл
 
Выбор между БД и файлом для меня очевиден: база создана для корректного и удобного чтения и записи данных (схема, транзакции, запросы, индексы). Дедупликацию по номеру за 10 минут в БД решает одним запросом, а с файлом пришлось бы самому решать блокировки и поиск. SQLite при этом тоже хранится в одном файле, не требует отдельного сервера и подходит под нагрузку лендинга.
 
## Как использовался ИИ
 
- **Инструмент:** чат Claude на бесплатном тарифе. Платной подписки у меня нет. Раньше в работе я использовал Cursor и Zed AI с подключением OpenAI API.
- **Фронтенд** сделан полностью с помощью ИИ.
- **Бэкенд** по большей части тоже сделан ИИ, с моими правками: у ИИ не было контекста проекта, и многое пришлось подгонять руками.
- **Ход работы:** Pydantic-модель по ТЗ → тесты → фронтенд (несколько итераций по стеку, в итоге React + Vite) → Docker и nginx → SQLite → защита от дублей → Уведомления в Telegram → GitHub Actions → сверка с ТЗ и правки (контент, бренд, OG-превью, вёрстка).

## Что можно улучшить
 
Проект сырой и делался второпях, главная цель была, чтобы всё работало. Код нужно тщательнее пересмотреть. Например, код отправки уведомлений в Telegram мне не нравится, но он работает и проходит тесты, поэтому я не стал тратить на него время. Таких мест много.
 
Из конкретного:
 
- **Маска телефона.** Для телефона стоило сделать маску ввода: жёсткий формат и удобство для пользователя.
- **Миграции.** Таблица создаётся через `create_all`, миграций нет.
- **Блокировка дублей.** `asyncio.Lock` работает только при одном процессе uvicorn.
- **Telegram.** Если контейнер перезапустится в момент отправки, сообщение потеряется (заявка при этом уже в БД).
- **Защита от спама.** Ограничения частоты запросов на API нет.
- **Источник заявки.** Метки живут в рамках сессии вкладки: если человек закрыл её и вернулся позже напрямую, источник будет пустым.
- **Исправления замечаний.** PageSpeed Insights выявил проблемы с производительностью.
